## 4. The tuning notebook (../tuning/)

- `hold_negotiation.txt`: run 2 changes the timers on a live session and
  captures the disagreement (negotiated 9/3 versus configured 3/1 on
  adjacent lines); timers only take effect when the session
  renegotiates.
- `bfd_peers.txt`: the armed BFD session (multiplier 3, 300/300, Up).
- `gr_state.txt` and `gr_restart.txt`: helper-only recorded, then
  `systemctl restart frr` on spine01 mid-ping costing 2 packets of 1122
  (0.18%), the NOTIFICATION reroute; leaf04 logs `Notification received`.
- `reconnect_default.txt` / `reconnect_tuned.txt`: link-up to Established
  2.4 s at connection-retry 10, 2.75 s at retry 1; the knob does not
  drive clean recovery.
- `stall_*.txt`: the over-tuning trap. 700 ms CPU stall on spine01 resets
  the 50 ms x2 profile (`stall_fast-bfd-700.txt`, ADJCHANGE 34 to 36) and
  leaves the 300 ms x3 profile untouched (`stall_safe-bfd-700.txt`).
  Calibration at 3000 ms resets anything; 400 ms resets nothing,
  implementations carry slack. `stress_*.txt`: raw CPU load never
  produced a flap, even sixteen hogs plus a hammered CLI against the
  50 ms profile (`stress_fast-bfd-heavy.txt`); the stall had to be
  total.
- `apply_*.txt`: every tuning command as applied, per device.
- `syntax_probes.txt`: the NVUE trees recorded for appendix B (timers
  hold range 3 to 65535, peer-group object, path-selection multipath
  aspath-ignore) and the FRR render.
